# publiccode yml Editor

This project is a fork of  [italia/publiccode-editor](https://github.com/italia/publiccode-editor), customized to align with the Design System of the Swiss Confederation 🇨🇭.

For details about the Swiss Design System, see:

- [Design System for the Swiss Confederation (GitHub)](https://github.com/swiss/designsystem)
- [Design System for the Swiss Confederation (Stoybook)](https://swiss.github.io/designsystem/?path=/docs/get-started--docs)
- [Design System Core Library (Figma)](https://www.figma.com/design/3UYgqxmcJbG0hpWuti3y8U/🇨🇭Design-System-Core-Library)

The application is live at: https://swiss.github.io/publiccode-editor/

## Branches

| Branch     | Purpose                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `cd-bund`  | Default branch. The Swiss editor: upstream publiccode-editor plus the adaptations for the Swiss Design System. All work happens here.       |
| `main`     | Unmodified mirror of upstream [`italia/publiccode-editor`](https://github.com/italia/publiccode-editor) `main`. Never commit to it.          |
| `gh-pages` | The built editor, generated by the deployment. Never commit to it.                                                                          |

## Deployment

The editor is deployed to the `gh-pages` branch automatically by the [deploy](.github/workflows/deploy.yml)
GitHub Action on every push to `cd-bund`.

## Syncing with upstream (publiccode-editor)

This editor follows upstream publiccode-editor. Upstream changes are **merged** into `cd-bund`
(not rebased), so the history of `cd-bund` is never rewritten and conflicts that were resolved once
do not come back.

### 1. Notification

The [Check upstream](.github/workflows/check-upstream.yml) GitHub Action runs every Monday (and can be
started manually from the Actions tab). If `italia/publiccode-editor` has commits that are not yet in
`cd-bund`, it opens an issue labelled `upstream-sync` with the list of commits and a link to the
changes. The issue is updated on every run and closed automatically once `cd-bund` is up to date.

The merge itself is not done by GitHub Actions: the built-in `GITHUB_TOKEN` is not allowed to push
commits that change files in `.github/workflows/`, which upstream changes regularly. Doing it with a
token that is allowed (a personal access token or a GitHub App) would tie the sync to a personal
account or require an organization-owned app. The merge is therefore done locally with your own
credentials.

### 2. Merge

Prerequisites: Git and Node.js/npm, a clean working tree and an up-to-date `cd-bund`.

```bash
git switch cd-bund
git pull
./scripts/sync-upstream.sh
```

The [script](scripts/sync-upstream.sh):

1. adds the `upstream` remote (`https://github.com/italia/publiccode-editor.git`) if it is missing and fetches `upstream/main`,
2. creates a branch `sync/upstream-<date>-<commit>` from `cd-bund` and merges `upstream/main` into it,
3. resolves the recurring conflicts automatically:
   - **Fork-owned files** (`publiccode.yml`, `CODEOWNERS`, `.github/workflows/deploy.yml`) always keep
     the `cd-bund` version (files deleted on `cd-bund` stay deleted). The list is `KEEP_OURS` at the
     top of the script. If upstream changed one of these files, the script prints a `git diff`
     command so you can check whether something should be ported by hand.
   - **`package.json`** is merged field by field: upstream wins for fields the fork did not change, the
     fork wins for fields it changed (repository, the added scripts, `bootstrap-switzerland` instead of
     `bootstrap-italia`, ...). `version` always follows upstream. Fields changed on both sides are
     listed for review.
   - **`package-lock.json`** is taken from upstream, with the package name and version set to ours,
     and then updated with `npm install --package-lock-only` because the fork's dependencies differ
     from upstream. This needs network access and moves `bootstrap-switzerland#gh-pages` to its
     latest commit.
4. commits the merge (as `chore:`, so release-please ignores it) if nothing else conflicts. Nothing is pushed.

If other files conflict (typically components, styles or translations the fork adapted), the script
stops and lists them. Resolve them, then:

```bash
git add <files>
git commit --no-edit
```

To abandon a sync instead: `git merge --abort && git switch cd-bund && git branch -D sync/upstream-...`
(the script prints the exact command).

### 3. Check

Build, lint and test the result, then check the editor locally, especially the parts upstream changed.
This needs Go in addition to Node.js (see [Setup](#setup)):

```bash
npm ci
npm run build
npm run lint
npm test
npm run dev
```

### 4. Publish

```bash
git switch cd-bund
git merge --ff-only sync/upstream-<date>-<commit>
git push origin cd-bund
git branch -d sync/upstream-<date>-<commit>
```

The push deploys the editor (see [Deployment](#deployment)) and the `upstream-sync` issue is
closed on the next run of the Check upstream workflow. If you prefer a review by someone else, push the
sync branch and open a pull request into `cd-bund` instead (merge it with a merge commit, not squash
or rebase, so the upstream history is kept).

Optionally update the `main` mirror as well (or use "Sync fork" on GitHub):

```bash
git push origin upstream/main:main
```

### Adding fork-specific files

If you change a file in a way that should always win over upstream (for example another workflow),
add it to `KEEP_OURS` in [`scripts/sync-upstream.sh`](scripts/sync-upstream.sh). Everything else is
merged normally, so keep the fork's changes to upstream files as small as possible to reduce conflicts.

## Description

This app helps you create and validate a [`publiccode.yml`](https://github.com/publiccodeyml/publiccode.yml) file for your project.
Simply fill out the form to generate a YAML file that meets the latest standards,
which you can then download or copy to your project's root directory.

You can also use the app to check and correct an existing `publiccode.yml` file.
Just upload the file to import it, and the app will validate and help fix any issues.


### Setup
#### Manual

First clone the repository:

```console
git clone https://github.com/italia/publiccode-editor.git
```

Navigate to the created directory, and run:

```console
npm ci
npm run build:licenses
npm run build:wasm
```

In order to run the development server locally, you should run:

```console
npm run dev
```

This will expose a webserver listening at [`http://localhost:8080`](http://localhost:8080).

#### Devcontainer

In order to develop in a container, you have to match the following criteria:

- VSCode installed
- Docker installed and running
- VSCode Devcontainer extension installed ([doc](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers))

You can clone the repo, run VSCode in that folder and run in a container.

Otherwise, you could simply click on following button.

[![Open in Dev Containers](https://img.shields.io/static/v1?label=Dev%20Containers&message=Open&color=blue&logo=visualstudiocode)](https://vscode.dev/redirect?url=vscode://ms-vscode-remote.remote-containers/cloneInVolume?url=https://github.com/italia/publiccode-editor)

This repo will be cloned in a Container Volume.

For more details, check Devcontainer documentation out at the following links

- [Specs](https://containers.dev/)
- [VSCode Devcontainer](https://code.visualstudio.com/docs/devcontainers/containers)

Every configuration process, such as dependency installation or wasm configuration, is handled by Devcontainer.

In order to run the development server, you should run:

```console
npm run dev
```

#### Static deploy

The editor is fully static and can be build with:

```console
npm run build
```

and then serve the content of `dist/` in production.

#### Docker

By running:

```console
docker build -t publiccode-editor .
```

you can build a Docker image. Subsequently, by running:

```console
docker run -p 8080:80 publiccode-editor
```

you can run the Docker container and see the results at [`http://localhost:8080`](http://localhost:8080).
